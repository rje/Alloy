## Release definition

The v1 goal is a dependable, native desktop workflow for creating an editable, dimensionally credible solid part and producing a correctly scaled, independently checked printable output. A first-time user must be able to launch a supported package, make or edit a constrained sketch, create and revise features, inspect the result, save/reopen/recover work, and export a valid mesh. Import and STEP exchange support the workflow where accepted by GATE-040. The release needs real application, geometry, persistence, input, GPU, visual, and output evidence; a compile, mock, issue count, or kernel-only fixture is not enough.

The project already defines a cumulative chain: `GATE-000 → GATE-005 → GATE-010 → GATE-020 → GATE-030 → GATE-040 → GATE-050`. The 2026-10-24 user decision moves native-backend GATE-045 beyond v1, retained under GATE-110; RHI-001/RHI-002 remain Todo. Keep the amended dependency chain authoritative. The workstreams below group its existing tasks into reviewable delivery slices; they do not replace its acceptance criteria. See [initial-build-readiness](../initial-build-readiness.md), [backlog rules](../backlog/README.md), and [workflow validation](../workflow-validation.md).

The existing `FULL-001` inventory owns cloud deferrals and unknowns; `GATE-110` owns eventual full noncloud reconciliation. For v1, retain a compact command matrix under the existing FND-008/compatibility and GATE-050 evidence: command and option, required selection, units/defaults, native keys/gestures, preview/commit/cancel, error behavior, history/edit support, export impact, and test fixture.
