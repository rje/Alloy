# Responsive Boundary Fill cell enumeration

REL-035/#478 addresses the corrected iron's 10.907-second UI-thread stall when Select Cells enumerates a four-tool Boundary Fill partition. Enumeration now reconstructs its own source geometry from immutable authored input and runs the unchanged partition kernel on the shared serial worker. The GUI accepts navigation, status and Cancel while it runs; document, revision, session, owner, input and generation guards prevent stale results from being applied. The existing cell cache, markers and explicit selection path apply only after completion. Cancel discards the result but does not interrupt OCCT.

On the saved accepted four-tool fixture, Select Cells submitted in 91.74 ms. Background work took 29.787 s: 19.161 s to reconstruct the private source and 10.326 s to partition it. During that interval, 113 status calls had a 0.274 ms median and 55.49 ms maximum; seven pans took at most 41.82 ms; the GUI heartbeat's maximum gap was 254 ms. The resulting cell ID, source-face references, marker, topology, volume and area exactly matched the prior synchronous fixture. It remained unselected until an explicit cell pick.

The already-responsive final Commit also passed in the same run: 66.82 ms submission, 31.413 s wall time, 103 status calls at most 75.87 ms, six pans at most 45.01 ms and a 204 ms maximum heartbeat gap. The accepted solid has one shell, eight faces, 20 edges, volume 856172.8343589634 mm³ and area 69287.64955744107 mm². Undo/redo, native save/reopen and stable face/edge IDs passed. Focused tests cover pending retries, frozen inputs, premature Commit refusal, stale result/Cancel, zero-cell failure and cached zero-cell retry; Surface Extrude regression checks also pass.
