# Explicit arc-endpoint to circle Tangent — SKT-123

Accepted 2026-10-18 after independent source, result and capture review. This bounded Alloy workflow relates the explicitly chosen start or end of one authored finite circular arc to a distinct full circle. The existing interior arc-circle mode remains separate. Public tutorial evidence supports explicit Tangent at an authored arc-circle endpoint; exact native selection/defaults/style remain unknown. The dated permitted evidence and proposed contract are external at `knowledge/specs/skt-022-endpoint-curved-tangent-2026-10-18.md` beneath `../Alloy-reference-records/`.

Activate Tangent, set Contact to **Arc Start to Circle** or **Arc End to Circle**, then pick the arc and circle in either order. Default **Curve Interior** retains the previous curve workflow. Changing Contact clears pending picks and keeps committed geometry. Each successful pair commits immediately, the command remains active for another pair, and Escape returns to Select. There is no separate preview/OK stage. Native popup keyboard choice, canvas picks, badge selection/Delete and Undo passed without inter-step focus repair; pointer-only popup row selection and physical hand input remain unqualified.

The shared commands are `sketch.constraintTool` with optional `endpoint: "start"|"end"`, `sketch.tangentContact` (omitting endpoint restores curve mode), and `sketch.constraint` with explicit endpoint and two `entityIds`. Direct `sketch.constraint` uses its explicit argument rather than inheriting the tool choice. `app.state.activeSession.tangentEndpoint` exposes the pending tool role. The authored `arcEndpointCircleTangent` record retains relation/entity IDs, canonical entity order, `side` (`1` external, `-1` internal), and `contact: {endpoint, pointId, sweepSign}`. Initial branch uses the existing nearest support-circle policy and refuses coincident-center/tied ambiguity; the retained outer/inner role and endpoint contact are independently checked after every solve. It never selects the opposite endpoint as a fallback. Unsupported endpoint pairs refuse through the shared pair-feedback path.

Duplicate relations, corrupted endpoint identity and coincident-center ambiguity refuse atomically.
