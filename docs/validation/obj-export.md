# Bounded OBJ output (XCH-010/#522)

Alloy's Save As Mesh dialog now offers OBJ alongside STL and 3MF. `document.exportObj` uses the same committed-body selector and background publication path. The accepted subset writes one deterministic, material-free file with a distinct generated group per selected closed solid instance, world Z-up coordinates and an explicit mm or in scaling choice. OBJ does not encode units; the dialog tells users to choose matching import units. The output inherits the shared indexed mesh's float32 millimeter coordinates, fixed 1e-6 mm seam weld and oriented manifold checks. It leaves authored features and undo state unchanged; cancellation before publication preserves an existing destination.

The [dated public workflow contract](../../../Alloy-reference-records/knowledge/specs/xch010-obj-output-2026-10-19.md) records the documented Browser Save As Mesh route, format, units and structure choices, plus the unknown defaults. The [external validation record](../../../Alloy-reference-records/validation/obj-export-2026-10-19/worker-checks.json) separates kernel, real-app API, Qt dialog-state and second-consumer checks. Focused core tests covered deterministic bytes, sphere seams, invalid selection/settings and atomic cancel; the shared 3MF indexed writer regression passed. A real-app replay exported one solid and two placed instances in mm/in, independently parsed bounds, triangle counts, closed oriented topology and volume, then edited a source solid and re-exported. A Blender 5.1.1 headless import separately read the two-group mm/in and edited files with expected bounds and volumes. The [GPU app capture](../../../Alloy-reference-records/validation/obj-export-2026-10-19/api/two-coupons.png) was inspected for the source scene, not as proof of the native dialog.

Qt tests verified the OBJ format entry, mm/in controls, one-file/no-material note and publication/cancellation state without claiming native pointer input. Native Mac system save chooser and Cancel remain XCH-012/#604. In this session, the desktop-control tool returned `cgWindowNotFound` for the private Alloy editor; that is a tool visibility limitation, not a demonstrated Alloy defect. The private editor was closed through Alloy's control API. XCH-013/#605 retains centimeter/meter/foot, One Body Per File, surface/mesh body and material/color/texture semantics. Windows/Linux runtime, physical OS input, exact reference defaults and matched visual parity remain unqualified. No paid CI run was started.
