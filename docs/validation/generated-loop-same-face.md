# Same-face generated loop Offset recreation (SKT-163/#596)

An earlier source-sketch edit can leave a planar-inset Offset's exact support face intact while changing every retained boundary edge. The async edit still fails atomically with `offset_lineage_unavailable`, but a narrowly classified, complete changed-boundary case now retains an inspectable repair session. The committed document, geometry, revision and history remain unchanged until repair is explicitly confirmed.

**Recreate Offset on Current Boundary** presents only the exact surviving face. The user confirms that face and the signed distance, then previews the changed loop key, new generated owner and fully evaluated downstream candidate. **OK** commits the source edit and recreation in one valid history entry. The sketch, support and unaffected authored data persist; owner, loop, profile, edge and contact IDs are new. Nested or whole **Cancel** restores the accepted state. An invalid preview disarms an earlier candidate, and a later committed edit invalidates the repair session.

This path requires one `planarInsetV1` owner on an earlier root planar face, a real source edit, an exact surviving support and a complete unique changed boundary. Missing, repeated, incomplete or ambiguous edge lineage and consumers of the old generated output refuse; a distinct face belongs to [SKT-162](generated-loop-replacement.md). No proximity matching or silent downstream retargeting occurs.
