# NAV-014: visible Pan, Zoom and Zoom Window

The navigation bar now offers checked Pan, Zoom and Zoom Window pointer tools. Their left-button drags use the same `view.pan`, cursor-anchored `view.zoom` and `view.zoomWindow` camera commands exposed to the local agent API. A Zoom Window rectangle is shown during the drag; its opposite corners may be drawn in either order. The orthographic camera fits the clipped rectangle using its **effective** zoom after the existing 0.1–10 clamp, then centers it. Rectangles smaller than 8 logical pixels on either axis are refused without changing the camera. Escape exits to ordinary selection; focus loss, hiding or deactivating the view cancels an unfinished gesture. Choosing Orbit or a different navigation tool cancels the pending gesture. These tool choices and drag sensitivity are Alloy policy where the public reference leaves details unknown.

The focused production-theme Qt fixture uses API setup to create a 46 × 27 × 13 mm box, then actual visible-button clicks and left-button Pan, Zoom and Zoom Window drags. It checks a no-drag click, checked tool transitions, actual view focus before Escape, unchanged authored document and undo state, and an ordinary body pick after exiting navigation. The Zoom Window drag and resulting real GPU view are captured under `../Alloy-reference-records/deliverables/nav014-2026-10-14/qt03/`; `ctest.log` reports 1/1 (Qt reports 3/3 including setup and cleanup) and the saved model is `navigation-tools.alloy`. The inspected result magnifies the selected region and remains readable; the top vertex approaches the viewport boundary because the selected rectangle omitted a small top margin. The rectangle and active button are visible in the drag capture. The first attempt lacked initial macOS window activation; the fixture now activates the window once before user steps, without an interstep focus repair. The double-click release guard was built after the focused run; out-of-view endpoint admission is source-reviewed, pending the next normal app relink.

This is one Qt pointer workflow on the current macOS host.
