# NAV-017: saved and reset Home

Home is now a document-saved camera pose and projection. The Browser **Named Views > Home** row has **Set Current View as Home** and **Reset Home** actions; the visible Home navigation control and Browser Home row restore the saved pose. Without a saved pose, Home retains Alloy's default isometric fit of visible geometry. Set and Reset are metadata undo entries that reuse the current geometry evaluation; moving the camera with Home does not edit the document. The saved record uses the same finite camera allowlist as custom named views, excluding sketch plane, active tool, input state and derived projection caches. Older files with no Home record use the default. Malformed saved Home records refuse to open atomically.

The focused production-theme Qt fixture creates an asymmetric 41 × 27 × 13 mm box via the shared API, moves to a perspective custom pose, then uses the actual Browser context menu to save it as Home. After a Top/Orthographic detour, an actual Home button click restores the saved projection, framing values and GPU direction/up; authored geometry and undo state stay unchanged. It then saves, switches tabs, returns, uses the Browser context menu to reset Home, checks metadata undo/redo, and clicks Home from Front/Orthographic to confirm the default isometric fit. API calls handle geometry setup, camera detours, history, storage and inspection. Both context-menu openers are Qt fixture events; menu-item and Home-button clicks are actual Qt pointer input.

The [external Qt01 evidence](../../../Alloy-reference-records/deliverables/navigation-home-2026-10-14/qt-01/) contains the exact 3/3 log, valid/invalid saved documents, and readable saved/default Home GPU captures. Public ViewCube help documents Go Home, Set Current View as Home and Reset Home but does not establish the default pose or exact stored fields; Alloy's default isometric-fit and document-scoped camera allowlist are explicit policies. Alloy currently uses a fixed Z-up frame, Front from −Y and Top from +Z. Configurable Front/Top/up remapping is retained in NAV-019/#443, and application input preferences in NAV-018/#439. Physical desktop gestures and other-platform/DPI behavior are not claimed by this Qt fixture.
