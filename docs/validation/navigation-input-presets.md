# Navigation input presets (NAV-018)

The public navigation-preferences record in `../Alloy-reference-records/knowledge/specs/navigation-preferences-orientation-2026-10-14.md` documents the default wheel/middle/Shift+middle map and an alternate Shift+Alt right/middle/left drag map. Alloy exposes these as neutral `default` and `shiftAlt` presets. Qt Alt maps to Option on macOS; drag sensitivity and the extra default Option+left pan are Alloy choices. The alternate map still uses a middle button for pan. Visible Pan, Zoom, Zoom Window and Orbit controls provide the separate no-middle-button route.

The preset is stored in app-scoped `QSettings`, never in a document or tab camera snapshot. The File → Navigation Controls menu and `view.inputPreset`, `view.inputPresetReset`, and `view.inputPresetInspect` share the view's input state. Switching or canceling clears an active chord; the right-drag path consumes its context-menu event. All three alternate chords dispatch existing `view.zoom`, `view.pan`, and `view.orbit` commands. No authored feature or history entry is created.

Focused Qt evidence: `../Alloy-reference-records/deliverables/navigation-input-presets-2026-10-14/qt-02/` has the 1/1 CTest result and GPU captures `alternate-navigation.png` and `navigation-controls-menu.png`. The production-themed fixture creates one 44 × 27 × 13 mm box through the shared API, sends actual Qt Shift+Alt middle/left/right drags to the viewport, checks camera pan/orbit/zoom plus unchanged authored state/undo, uses an actual menu-row pointer click after a programmatic menu opener, saves, closes, and constructs fresh windows against isolated app settings. The alternate preset survives the restart; reset restores the default without document mutation. The menu capture shows the checked preset and binding text. Interruption and
alternate double-click cancellation received a subsequent source-review fix,
reusing the existing gesture cleanup. Context-menu event suppression is
source-reviewed; the fixture does not deliver a native OS context event. This is Qt event routing on this macOS host, not a physical mouse/trackpad or Windows/Linux input qualification; NAV-008 retains that gate.
