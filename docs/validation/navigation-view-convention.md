# Document view convention (NAV-019)

The external public-source handoff `../Alloy-reference-records/knowledge/specs/navigation-preferences-orientation-2026-10-14.md` documents Z-up/Y-up preferences and Set/Reset current cube face. Exact remapping math and the behavior of an independent Front versus Top reset are unspecified. Alloy stores one coherent orthonormal right/back/up frame in the document. Missing metadata preserves the old Z-up orientation. A Y-up choice uses a canonical frame with Top along world +Y; Set Current View as Front or Top derives the whole frame from the actual live camera direction/up, including oblique poses. Reset returns the whole frame to canonical Z/Y. Immediate document scope, oblique-pose mapping, and whole-frame reset are Alloy policies, not claims of exact reference behavior.

The Browser Up row and Front/Top context actions use `view.conventionUp`, `view.conventionSet`, and `view.conventionReset`. Each commits one metadata history step with reused geometry evaluation and strict finite right-handed basis validation. The cube's local OCCT transform rotates the visual labels and hit regions together; all standard camera commands, adjacent face tests, hybrid principal-face projection, and Constrained Orbit use that same frame. Scene center, pan, selection, sketch support frames and authored geometry remain world-space. The live camera is frozen to a world pose before a convention edit, so the edit does not move it. Saved Home/named views remain absolute world camera poses; they are not rewritten. The Up indicator reports the actual cube vertical axis separately from the selected canonical default after an oblique remap.

Focused Qt/GPU evidence: `../Alloy-reference-records/deliverables/navigation-view-convention-2026-10-14/qt-04/` contains the 1/1 CTest log, a 47 × 26 × 15 mm asymmetric box fixture and captures of Y-up and an oblique Front cube. The fixture uses one actual Browser context-menu action and one hit-owned orientation-cube face click; setup, six named-face visits and hybrid-projection checks, Top remap, Home/named restore, history, save/reopen and reflected-frame refusal use the shared API. It confirms the unchanged live camera during convention edits, explicit Front/Top direction-vector assertions, a retained world-space body pick, unchanged authored feature data, reset/undo/redo, persisted frame and atomic malformed-file refusal. This is one macOS Qt/GPU state, not a six-face native-click corpus, OS input-matrix qualification, or an exact reference screenshot match.
