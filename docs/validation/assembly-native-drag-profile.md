# REL-011: bounded native assembly drag profile

The bounded measurement completed: native correctness passes, but the predeclared 100 ms development-preview dispatch budget is **not met** (median 159.925 ms, maximum 170.737 ms). The accepted saved 3-Revolute/1-Cylindrical piston mechanism is used directly; this task changes only the focused Qt test and this receipt. No solver tolerance or production behavior changes.

The predeclared development-preview latency target is at most 100 ms per synchronous move dispatch. Six samples cannot establish a statistical p95, so the report lists every raw duration, the maximum and median. A 50 ms dispatch is an aspiration, not the acceptance budget. This is not a smooth-motion or 60 Hz target. The historical 223 ms single event was measured on a different event/fixture run and is contextual only; no matched pre-REL-010 native baseline exists.

`AssemblyCoupledControlsTest::nativeDragProfile` opens the accepted fixture and performs one press, six distinct screen-angle moves: a first movement computed from the observed screen radius to clear a 6-pixel chord (at least 2°), then five further 2° increments, and one release. Initial activation, view setup, visible Upper Arm hit search, inspection and the before capture occur before measurement. Focus is observed after press and each move, without repair. There is no screenshot, model inspection, capture recording or deliberate pacing sleep inside the six-event sequence. Each cumulative movement must clear the existing 4-pixel drag threshold, and each dispatch must actually perform a graph solve. The first step is computed before input, rather than selected by retries. After each dispatch the test drains available Qt events while excluding user input, allowing queued presentation work to run before the next move.

Available timing buckets are event construction, complete synchronous dispatch, post-dispatch Qt event drain, press, release, before/after screenshot commands and Revert. `AssemblyGraph::solveCount` records graph solve counts separately for dispatch and event drain. Dispatch includes input routing, graph solving and synchronous presentation; the existing instrumentation cannot time those phases independently. Event-drain time includes deferred paint and other queued Qt work, and does not establish GPU completion or display latency. Screenshot timing includes the complete shared capture command, framebuffer readback/PNG and command refresh. It is outside drag timing. OS event acquisition, solver-only duration, GPU duration and physical pointer latency remain unavailable.

The test verifies a meaningful staged driver angle and multiple moved occurrences, original joint-origin/axis tolerances, full Lower Arm Pin, exact unchanged authored data and exact Revert of occurrence poses. These reuse accepted authorities rather than rerunning geometry, save/reopen or export validation. A passing correctness test does not imply the latency target was met; the profile records that outcome separately.

The one focused `nativeDragProfile` run passed 3/3 Qt checks in 4.733 s. Every move performed exactly one graph solve; no graph solve occurred during the post-dispatch event drain. Three occurrence poses changed, all four original joint relationships stayed within the accepted tolerances, the complete Lower Arm Pin stayed exact, authored data stayed exact and Revert restored the baseline occurrence records exactly. The inspected before/after captures visibly show the Upper Arm and coupled piston changing pose with readable smooth shaded geometry. Static captures do not establish continuous animation quality.
