# REL-022: reachable primitive dock at minimum window size

The Box and Cylinder dock now keeps Preview, OK, and Cancel in a fixed footer below a vertically scrollable form. `QFormLayout::WrapLongRows` keeps labels and numeric editors inside the narrow dock rather than clipping their right edges. The form, footer, and existing shared primitive commands remain the same controls at normal and minimum window sizes.

The focused production-theme Qt run at 1360×850 and 1040×640 passed [3/3](../../../Alloy-reference-records/deliverables/rel022-primitive-dock-2026-10-14/qt-04/qt.log). After layout settled, the form content and viewport were 312/312 logical pixels at normal width and 296/296 at minimum width. [Normal Box](../../../Alloy-reference-records/deliverables/rel022-primitive-dock-2026-10-14/qt-04/normal-box.png), [minimum Box after keyboard traversal](../../../Alloy-reference-records/deliverables/rel022-primitive-dock-2026-10-14/qt-04/minimum-box-scrolled.png), and [minimum Cylinder](../../../Alloy-reference-records/deliverables/rel022-primitive-dock-2026-10-14/qt-04/minimum-cylinder.png) captures show legible fields and the fixed footer. The test checks each numeric field's horizontal bounds and actual `widgetAt` ownership of the footer buttons.

The fixture opens Box and Cylinder through the shared control API. It then clicks Name in the real Qt dock, tabs to the lower Z editor, observes that scrolling makes the entire editor visible, enters 5, and clicks Preview and OK on their actual widgets. Preview leaves the authored feature list empty; OK commits one Box with `zMm=5` and volume 6000 mm³; Undo removes it. A later hit-owned Cylinder Cancel leaves authored features and undo state unchanged. The fixture saves its empty model before closing. These are Qt input and shared-document checks, not physical keyboard or pointer-device evidence.

Earlier focused attempts remain [preserved](../../../Alloy-reference-records/deliverables/rel022-primitive-dock-2026-10-14/qt-01/qt.log): the macOS overlay scrollbar was not visibly drawn despite a positive scroll range; a delivered wheel event did not move that scrollbar in the attempted route; and a nested `QVERIFY` inside a void test lambda caused a false continuing test after a geometry failure. The final run uses an outer `QTRY_VERIFY` for settled geometry and keyboard traversal. Pointer-wheel scrolling is unqualified and remains part of REL-013. This receipt establishes the reachable lower field and fixed footer at these two sizes on the tested macOS Qt runtime, not every platform or input device.
