# Retained planar Offset Face (SOL-067/#512, SOL-072/#598)

Alloy now offsets one selected planar face of a closed solid along its outward normal using a signed distance. It retrims neighboring faces through OCCT's local offset operation, retains one editable `faceOffset` history feature, and gives the moved face an exact feature-owned support identity. The Solid > Modify > Offset Face route, `solid.faceOffset` local command, native dock and timeline edit use the same document operation. The dock supports command-first viewport picking, active mm/in distance, live preview, OK, Cancel and Escape. A zero initial distance is an Alloy choice because the public references do not establish a default.

The [dated public command contract](../../../Alloy-reference-records/knowledge/specs/sol067-planar-face-offset-2026-10-19.md) covers the documented location, signed distance, selection, preview and retained history. The [external validation receipt](../../../Alloy-reference-records/validation/sol067-face-offset-2026-10-19/receipt.md) separates focused kernel, native input, real-app API, GPU and STL evidence. A box and an angled-wall solid pass positive and negative offsets. In the real app, a sketch point and countersunk Through All hole on the moved face survive an offset edit; a collapsing inward edit refuses without changing authored state. Undo/Redo, save/reopen and independently parsed STL bounds pass. Native Qt input opens the Modify menu, picks the face at the actual viewport hit, changes the signed field, cancels and then commits without harness focus repair between user steps. The edit dock is checked with `feature.editDialog` and a negative value; a physical timeline-button click remains unqualified. The inspected capture reports Apple M4 hardware OpenGL, 4× MSAA and a native 2× framebuffer.

SOL-072 adds a GPU canvas arrow and signed distance label anchored to the original face frame. In an oblique view, dragging the arrow updates the same active command, native Distance field, disposable solid preview and retained history as numeric entry. The focused native pointer test crosses positive → zero → negative in one held gesture, checks actual widget hits, and cancels without changing authored geometry. A view aligned with the face normal shows a readable “Rotate view to drag” cue and keeps numeric entry available instead of guessing a pointer direction. [Dated public handle research](../../../Alloy-reference-records/knowledge/specs/sol072-offset-face-manipulator-2026-10-19.md) and [native zero/negative captures](../../../Alloy-reference-records/validation/sol072-face-offset-handle-2026-10-19/) are kept outside the repository; the public illustration is not a matched-size/theme reference, so pixel parity is unqualified.

This child supports one planar face on one source solid. Multi-face and tangent-chain selection, surface bodies, and source-feature modification remain outside this result. Exact reference-product styling and physical OS input remain unqualified. Offset boundary-edge and solid-edge references are conservatively unavailable until exact lineage can be established; they are not silently matched by proximity.
