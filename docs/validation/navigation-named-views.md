# NAV-016: retained custom named views

Alloy's Browser Named Views folder can save the current camera as a custom row, rename that row, restore it by clicking, and delete it. `view.namedCreate`, `view.namedRename`, `view.namedRestore`, and `view.namedDelete` use the same commands as the Browser. The saved document record has a stable UUID, a unique name, and an allowlisted camera pose: projection policy, direction/up, framing center, scale, zoom, and pan. It excludes sketch planes, active navigation tools, input state, and resolved projection caches. Creating, renaming, and deleting a view each use a document metadata undo entry with the existing evaluation; restoring changes only the live camera. The active tab's selection and modeling state stay intact. Legacy files without named views still open; malformed saved camera records refuse to open before replacing the current document.

The focused production-theme Qt fixture creates a box through the shared API, sets a perspective custom camera, then opens the actual Named Views context menu on its Browser row and clicks **New Named View**. Actual Browser input edits its name to **Assembly Angle** and presses Return; the context-menu **Rename** route then changes it to **Assembly View** with Return. Clicking that row restores the perspective pose after changing to Home/Orthographic. The fixture compares GPU direction/up, projection policy and framing fields, checks unchanged authored/undo state on restore, saves and switches tabs, deletes then undoes/redoes the retained row, and checks malformed-file refusal plus valid reopen. The actual capture shows the custom row and restored GPU box; geometry and camera setup, deletion, history, storage, and inspection use the shared API. Context-menu opening is a Qt harness event; the menu items, inline edits, and restore row use Qt pointer/key input. Preservation of a nonempty modeling selection during restore is source-reviewed, not exercised by this idle fixture.

The [external Qt11 evidence](../../../Alloy-reference-records/deliverables/navigation-named-views-2026-10-14/qt-11/) has the Browser/GPU captures and saved valid/invalid documents; its [exact log](../../../Alloy-reference-records/deliverables/navigation-named-views-2026-10-14/qt-11.log) reports 3/3 Qt checks passed. The fixture passively confirms no Qt popup remains after Rename before capturing. The research contract is in `../Alloy-reference-records/knowledge/specs/navigation-projection-named-views-handoff-2026-10-14.md`. Public documentation establishes the Browser New Named View/rename workflow, but does not establish exact camera persistence schema or every gesture; those are Alloy policies. Home/front/up configuration and navigation preferences remain NAV-017/NAV-018. Physical desktop input, alternate host/DPI behavior, and portable packaging are not established by this fixture.
