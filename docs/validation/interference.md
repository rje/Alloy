# Two-solid Interference and clearance inspection — DOC-037/#521

Accepted bounded result: **Inspect > Interference** selects exactly two committed closed solids and computes a transient, read-only result. Positive common volume is reported as overlap in mm³; separated bodies report the OCCT minimum distance and closest points in mm; contact within tolerance reports touching. The local `inspect.interferenceResult` API and native panel use the same evaluation, stable body/occurrence identities and structured errors. A highlighted intersection or nearest-point cue is drawn in the GPU viewport. No feature, history item or saved analysis node is created.

Independent real-app [fixture](../../tests/interference_independent_api.py) used a 10 mm cube and a second box. Exact analytic overlap was **32 mm³** (reported 31.999999999999993), then **2 mm clearance** after moving the second box, then touching at 0 mm. Editing its source from x=8 to x=7 recomputed overlap to **48 mm³**; Undo/Redo and save/reopen reproduced 32/48/48. Inch display converted only presentation; canonical millimeter values remained fixed. Zero/duplicate/stale body selections refused without mutation. The inspection left authored data, revision, dirty state, Undo and saved bytes unchanged. Focused core checks independently compare OCCT common/distance and exercise occurrence identities.

The final compiled Qt actual-hit sequence opened the Inspect menu, picked two canvas bodies and computed the 32 mm³ result, then cleared and closed the panel, 3/3 without focus repair. The final `capture.screenshot` whole-app image shows both gray bodies, cyan selection outlines, orange overlap and a readable result panel. The first `QWidget::grab()` capture was black over the OpenGL drawable; that was a capture method error and was replaced with the GPU composited capture. The Apple M4 renderer reported OCCT OpenGL 4.1 through Metal, DPR 2, with a 2296×1216 native viewport framebuffer. The private validation editor was closed. Local Release build used the accepted Qt 6.11.2 SDK and `-j4`; no CI was launched.
