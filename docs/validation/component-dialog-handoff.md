# Component dialog activation handback

FND-027/#401 is a bounded Qt focus correction for component conversion, New Component, and Rename Component dialogs. When one of these dialogs finishes, Alloy queues one parent-window activation only if the same design tab and document are current, the application remains active, the parent is visible, and no other modal window, popup, or active window owns input. It does not set focus to a child widget or retry activation.

The cumulative native piston continuation reproduced a focus gap after conversion: the modal closed while Alloy remained application-active, but no Qt window activated. `native-12` and `native-13` in the external `piston-native-workflow-2026-10-14` deliverable preserve the read-only event trace and application state. With the correction, `native-14` passively regained the main window after conversion and reached New Component, where the same gap appeared. `native-15` passively regained the main window after conversion, New Component, and Rename, then created three native As-Built joints before a separate upper-bore hover visibility failure. Its log and failure capture are in the same external deliverable. This establishes activation handback for those three transitions; it does not establish the complete piston workflow or OS physical-input parity.

The private editor was closed after each attempt. The harness uses one initial macOS application activation and makes no focus repair between user steps. Rename shares the guarded component-dialog lifecycle and was exercised in `native-15`; no broader modal-dialog behavior is claimed.
