# Circular Body Pattern

Public source record `ornament-pattern-20261013` establishes Bodies, one selected
seed, the vertical rotation axis, Full 360 and total Quantity 8 including the
seed. The image shows all eight occurrences active. The exact selected source
axis object versus edge, angular direction, phase and initial quantity default
are unknown. Detailed provenance and images remain in the external knowledge
record. Suppression and additional pattern modes are outside this bounded slice.

Alloy retains `{kind:originAxis,axis:Z}` in the feature's owner. The native Axis
selector explicitly chooses Origin Z; it is an adapted selection rather than a
claim of direct source axis picking. Full distribution uses positive CCW angles
`2*pi*i/quantity`, phase zero, with integer quantity 2..128. The initial UI quantity
3 and first valid preview auto-fit are declared Alloy policies, not source defaults.

The authored `circularPattern` holds one source body UUID, axis, extent `full`
and quantity. Occurrence zero keeps the original body, producer, face and edge
identities. Other bodies use UUIDv5 of feature UUID, occurrence index and source
UUID; their mapped supports and edges use corresponding source identities.
They are evaluated derivatives, with no independently authored clone features.
The bounded `SolidTransform` helper reuses the existing exact OCCT transform
history path used by Mirror. Every mapped face/edge must be an actual unique
result descendant, and every occurrence preserves one valid closed solid and
its volume. Current owner placements are identity; cross-owner dependencies refuse.

Generated body ownership and active-history dependencies are registered before
later features evaluate. Quantity changes retain unaffected prefix UUIDs;
removing an occurrence referenced downstream refuses atomically. Meaningful source
edits rebuild all occurrences. Body inspection includes `circularPattern` with
feature/source IDs, index, total quantity, actual angle, retained axis and extent.

`solid.circularPattern` and its Dialog use the same candidate and document commit.
Native body picking, Origin Z selection and quantity editing build disposable real
OCCT previews. The blue selected seed stays visible; neutral derived copies appear
without a duplicate seed. Cancel/Escape discard previews, OK commits one feature,
and history edit stages the actual earlier seed. Count, axis and source inputs are
shared with inspection; only supported Full/Bodies controls are presented.

A simple eight-spoke/hub Join verifies generated-body dependencies independently.
It does not establish the exact-offset ornament Join or full tutorial acceptance;
those remain tracked by #265 and #264.
